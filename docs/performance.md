# Бюджеты производительности

Это **предварительные цели, не результаты замеров и не обещание готовой производительности**. LR-001 выбирает реальные устройства и утверждает достижимые значения; изменения документируются с обоснованием.

## Начальные ориентиры

| Показатель | Цель | Как измерять |
| --- | --- | --- |
| Загрузка приложения | ≤ 35 MiB на устройство | Android split delivery / iOS app thinning, release, arm64; без книг и отладочных символов |
| Установка | ≤ 100 MiB | Чистая установка, без пользовательских данных; отдельно от загрузки |
| Холодный запуск библиотеки | p95 ≤ 2 с | До доступного управления, 1 000 записей |
| Первое открытие обычной книги | p95 ≤ 3 с | Локальная книга до 20 MiB после импорта |
| Открытие большого документа | p95 ≤ 5 с до первой страницы | PDF/DjVu до 200 MiB и 1 000 страниц, без полного рендера |
| Перелистывание подготовленной страницы | p95 ≤ 100 мс | От ввода до отрисовки, отдельно первый рендер |
| Память текстового чтения | пик ≤ 150 MiB | Android total PSS; iOS physical footprint |
| Память PDF/DjVu | пик ≤ 250 MiB | Включая native buffers, UI и WebView-процессы где доступны |
| Покой на странице | средний CPU < 1% за 60 с | После завершения рендера; указать метод нормирования CPU |
| Кеш производных данных | ≤ 200 MiB по умолчанию | Общий LRU-лимит; исходные книги и шрифты считаются отдельно |

Метрики памяти Android/iOS не идентичны: отчёт хранит исходные значения и инструмент измерения. Не смешивать universal APK, AAB/IPA и реальную загрузку на устройство.

## Воспроизводимая процедура

1. Выбрать минимум один ограниченный Android с 3–4 GB RAM и один старший по возрасту поддерживаемый iPhone. Записать модель, ОС, свободную память, состояние батареи и температурный режим.
2. Зафиксировать release-коммит, версии SDK/движков и состав включённых форматов.
3. Использовать лицензированный корпус: маленькая книга; сложный EPUB; FB2 со сносками и Windows-1251; скан; PDF/DjVu на 1 000 страниц; огромная картинка; повреждённый документ.
4. Для временных метрик выполнить 20 повторов, разделяя холодный и тёплый кеш; привести p50/p95 и максимум.
5. Пройти 30 минут чтения с одинаковым сценарием перелистывания, яркостью и сетевым режимом; записать энергию/разряд, CPU, память и нагрев. Сравнить с пустым экраном приложения при той же яркости. Допустимый прирост энергии определить по прототипу в LR-001, не по случайному проценту батареи.
6. Проверить уход в фон, блокировку, возврат, отмену импорта и предупреждение о памяти. После ухода в фон не остаётся непрерывного рендера или опроса.
7. Сохранить отчёт с условиями, исходными данными и регрессиями; в CI отдельно контролировать размер артефактов и пороги, где измерение стабильно.

Большие книги не должны требовать памяти пропорционально всему документу. Нельзя достичь бюджета удалением обязательного формата либо скачиванием движка после установки без отдельного пересмотра требований.
