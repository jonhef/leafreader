# Архитектура: предварительное решение

Статус: предложение до завершения LR-001, LR-002 и LR-003. Зависимости пока не установлены.

## Кандидаты

| Вариант | Причина рассмотреть | Что проверить |
| --- | --- | --- |
| Swift/SwiftUI + Kotlin/Compose | Системные API и независимое управление ресурсами | Дублирование логики, размер Compose и чтения, стоимость поддержки двух приложений |
| Flutter + нативные мосты | Общий интерфейс и бизнес-логика | Прибавка runtime, зрелость мостов, копирование растров между движком и UI |
| Kotlin Multiplatform + нативный UI | Общая модель и часть логики | Усложнение сборки и границ библиотек, реальная экономия разработки |

Исходная гипотеза — два нативных клиента. Нельзя объявлять этот вариант самым лёгким без одинаковых release-замеров. Прототипы сравниваются на одних документах; решение закрепляется ADR с выбранными версиями и минимальными ОС. Desktop и web не входят в текущую цель.

## Слои

1. **UI:** библиотека, экран чтения и настройки, доступность и платформенная навигация.
2. **Сценарии:** импорт, открытие, сохранение позиции, применение настроек, удаление.
3. **Данные:** локальная БД, файлы книг и шрифтов, ограниченный восстанавливаемый кеш.
4. **Адаптеры форматов:** FB2, EPUB, PDF, DjVu; тяжёлая работа вне UI-потока.

Каждый адаптер объявляет возможности: reflow, шрифты, текстовый поиск, оглавление, фиксированные страницы. UI показывает только применимые настройки.
Контракт: open / metadata / toc / navigate / currentLocation / close, отмена фоновой работы и ошибки. Конкретные интерфейсы определяются в LR-008.

## Позиция и данные

- У книги есть собственный ID, checksum для дубликатов, исходный формат, управляемый путь и метаданные.
- Позиция — версия схемы и форматный locator; процент служит только отображением.
- EPUB: locator выбранного движка; FB2: стабильный ID раздела + смещение; PDF/DjVu: индекс страницы + положение в ней.
- Смена шрифта, ориентации и размера текста не должна сбрасывать место чтения.
- Исходный документ сохраняется. Производные файлы и миниатюры можно восстановить.
- Импорт атомарный: временный файл → проверка → перенос → запись в библиотеку; неудача не оставляет полукнигу.
- Удаление кеша не удаляет книги, закладки или пользовательские шрифты.

## Движки

Readium Mobile заявляет EPUB и PDF, а также инструменты Swift и Kotlin: [официальный обзор](https://readium.org/mobile/). Он кандидат для EPUB; поддержка FB2 и DjVu из этого не следует.

Для FB2 рассматривается потоковый XML-парсер и преобразование в локальное представление, совместимое с текстовым движком. Необходимо сохранить сноски, ID разделов, кодировки и позиции после обновления кеша.

Для PDF сначала проверить системные PDFKit (iOS) и PdfRenderer (Android); различия в API и оглавлении могут потребовать альтернативы. Официальные справочники: [PDFKit](https://developer.apple.com/documentation/pdfkit), [PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer).

Для DjVu исследовать доступные декодеры, сборку arm64 и совместимость с актуальными требованиями платформ. [Условия DjVuLibre](https://djvu.sourceforge.net/licensing.html) требуют отдельной проверки. Без приемлемого решения нельзя считать MVP выполнимым.

## Ограничение ресурсов и безопасность

Загружать главы и страницы по запросу; хранить только ограниченное соседнее окно страниц. Растры рендерить под viewport, большие страницы — фрагментами. Освобождать декодер и кеш при закрытии книги и предупреждении о памяти.

Не загружать весь архив, XML или документ в память. Ограничить объём распаковки, глубину XML, число элементов и размер изображений. Запретить внешние сущности, выход путей из каталога импорта, скрипты и автоматические сетевые запросы книги.
Шрифты валидировать и регистрировать в пределах приложения, не устанавливать системно. Фоновая индексация отменяется, когда она больше не нужна.
