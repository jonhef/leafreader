# Участие в проекте

В проекте реализован предварительный MVP. Сначала выберите задачу в [локальном трекере](issues/README.md) и убедитесь, что её зависимости завершены.

## Работа с задачами

- ID вида LR-001 постоянны и не зависят от будущих номеров GitHub.
- Статусы: open → in-progress → review → done; blocked означает указанную причину и следующий шаг.
- Обновляйте статус и в файле задачи, и в индексе. Отмечайте критерии только после проверки.
- Для нового issue используйте [шаблон](issues/TEMPLATE.md), присвойте следующий ID и добавьте строку в индекс.
- P0 — блокирует MVP; P1 — необходимо для завершения MVP; P2 — после MVP. Приоритет не отменяет зависимости.
- Изменение требований, архитектуры и численных бюджетов фиксируйте явно, с причиной и результатами измерений.

## Изменения

Одна ветка и логически связанное изменение на задачу; пример имени: feature/LR-010-fb2.
В описании изменения укажите проблему, результат, ID задачи, проверки на iOS/Android и известные ограничения.
Изменения интерфейса сопровождайте снимками обеих платформ. Изменения движка — проверкой документов и замерами памяти.

Тестируйте важное поведение, повреждённые входные файлы и сохранность библиотеки. Команда полной проверки: `npm run check`; Android: `npm run mobile:sync`, затем Gradle assembleDebug; iOS: Xcode на macOS. Не добавляйте пустые тесты и фиктивные инструкции запуска.

## Зависимости и данные

До добавления зависимости укажите точную версию, источник, лицензию, транзитивные зависимости и влияние на размер сборки. При необходимости обновите сведения о сторонних лицензиях.
Не используйте неподтверждённо совместимые GPL/AGPL-компоненты в поставке.
Не коммитьте сертификаты, пароли, личную библиотеку и коммерческие шрифты.
Каждый распространяемый тестовый документ должен иметь автора, источник и условия использования.

Вклад в собственный код и документацию предоставляется под MIT; сохраняйте авторство и обязательные уведомления сторонних компонентов.
