# Leaf Reader

Локальная читалка для iPhone и Android с интерфейсом по мотивам Thorium Reader.

**Версия 0.1.0 — работающий предварительный MVP, не готовый магазинный релиз.** Реализованы четыре формата и свои шрифты. Android-проект собирается; iOS-проект подготовлен, но ещё не собран на Mac и не проверен на iPhone. WebKit-тесты не заменяют эту проверку.

## Возможности

- **FB2:** главы, изображения, сноски, UTF-8 и Windows-1251.
- **EPUB 2/3:** изменяемая и фиксированная вёрстка, оглавление, внутренние ссылки.
- **PDF:** постраничное чтение, масштаб, оглавление при наличии.
- **DjVu:** одиночные и bundled multipage документы, страницы и масштаб.
- Свои **TTF/OTF**, выбор семейства/начертания, проверка файла и удаление.
- Библиотека с поиском по названию/автору, сортировкой, плиткой и списком.
- «Продолжить чтение», сохранение места и закладок между запусками.
- Поиск внутри FB2/reflow EPUB, темы (светлая/тёмная/сепия), размер, поля, интервал, листание/прокрутка.
- Импорт через системный выбор файлов. Нативные обработчики «Открыть в…» добавлены, требуют проверки на устройствах.
- Нет аккаунта, сервера, рекламы, аналитики или автоматической отправки книг.

Шрифт меняется в FB2 и **reflow EPUB**. PDF, DjVu и fixed-layout EPUB сохраняют исходную страницу. OCR, DRM, редактирование PDF, синхронизация, FB2 ZIP и indirect DjVu не входят в эту версию.

## Запуск на компьютере

Нужен Node.js 22.12+ (проверено на 24.14.1).

```sh
npm ci
npm run build
npm run preview
```

Откройте адрес, напечатанный сервером, обычно http://127.0.0.1:4173. Для разработки: `npm run dev`. Нажмите «Добавить книгу» или «Открыть пробную книгу».

Это локальный браузерный предпросмотр, не установленная PWA. Офлайн-ресурсы встроены в мобильные приложения; браузерному предпросмотру нужен запущенный локальный сервер. Книги хранятся в профиле браузера/приложения. Удаление его данных удалит библиотеку; сохраняйте оригиналы.

## Android

Проект: `android/`. Минимум Android 10 (API 29), актуальный Android System WebView. Требуются JDK 21, Android SDK 36 и Build Tools 35.0.0/36.0.0; `JAVA_HOME` и `ANDROID_HOME` должны указывать на установленные инструменты.

```sh
npm run mobile:sync
cd android
./gradlew assembleDebug
```

В PowerShell используйте `./gradlew.bat assembleDebug`.
Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Это отладочная сборка для проверки, не релиз для Google Play.

## iPhone

Проект: `ios/App/App.xcodeproj`. Целевая минимальная версия iOS 17.4; окончательная матрица устройств требует проверки. Нужны macOS, Xcode 26+ и Swift Package Manager.

```sh
npm ci
npm run mobile:sync
npx cap open ios
```

В Xcode выберите команду подписи и iPhone либо симулятор. Для проверки без подписи:

```sh
xcodebuild -project ios/App/App.xcodeproj -scheme App -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

Сборка iOS и импорт из Files/Share Sheet не проверены в текущей Windows-среде. Автоматическая проверка для macOS описана в `.github/workflows/check.yml`, но удалённый CI ещё не запускался.

## Проверка

```sh
npx playwright install chromium webkit
npm run check
```

Команда создаёт синтетические книги, выполняет модульные проверки, собирает приложение и запускает пользовательские сценарии в Chromium и WebKit. Проверяются настоящие пиксели PDF/DjVu, EPUB fixed layout, шрифты, поиск, закладки, повторное открытие, повреждённые файлы и блокирование активного содержимого EPUB.

[Отчёт проверки](docs/verification.md) отделяет подтверждённое от незавершённого.

## Размер и ограничения

Интерфейс использует системный WebView, без собственного Chromium и тяжёлого UI-фреймворка. Движок PDF загружается только при открытии PDF. DjVu декодируется в Worker, изображение одной страницы ограничено 16 мегапикселями. EPUB/PDF читаются из хранилища диапазонами, кеш оригинала — два фрагмента по 1 MiB.

Лимиты первой реализации: книга до **128 MiB**, FB2 до **24 MiB**, шрифт до **12 MiB**, EPUB до 5 000 ресурсов/256 MiB распакованных данных, отдельный ресурс до 24 MiB. FB2 пока разбирается целиком; DjVu держит исходный буфер в памяти Worker. Большие/сложные книги могут потребовать дальнейшей оптимизации.

Размер веб-ресурсов и APK указан в отчёте проверки. Бюджеты памяти, батареи, нагрева и p95 на телефонах **ещё не подтверждены**. Поддержка всех вариантов реальных документов и доступность со скринридерами также требуют расширенного корпуса и ручной проверки.

## Устройство проекта

- `src/` — интерфейс, локальные данные, безопасность и адаптеры форматов.
- `vendor/` — исходники движков с зафиксированными ревизиями и лицензиями.
- `android/`, `ios/` — мобильные проекты и обработка внешних файлов.
- `tests/` — модульные и браузерные проверки, синтетические книги и открытые шрифты.
- `issues/` — локальные задачи и критерии приёмки.
- [Архитектура](docs/architecture.md), [дизайн](docs/design.md), [производительность](docs/performance.md), [вклад](CONTRIBUTING.md).
