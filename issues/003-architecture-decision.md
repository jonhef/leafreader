## Цель

Выбрать реализацию по замерам, доступности движков и стоимости поддержки.

## Объём работ

- Сравнить нативные клиенты, Flutter и Kotlin Multiplatform по критичным ограничениям.
- Зафиксировать выбранный стек, версии инструментов и границы модулей в ADR.
- Уточнить стратегию FB2, локального хранения и общих тестовых контрактов.

## Критерии готовности

- [ ] ADR содержит выбранный вариант, отклонённые альтернативы и причины.
- [ ] Зафиксированы минимальные ОС, версии SDK и движков, сборочные зависимости.
- [ ] README и architecture.md отражают решение без неподтверждённых обещаний.

## Проверка и результат

Приложить к задаче ссылки на изменения и результаты проверки критериев. Для исследовательской задачи — решение и измерения; для реализации — сценарии обеих платформ, существенные тесты и известные ограничения. Отмечать критерии после проверки.
