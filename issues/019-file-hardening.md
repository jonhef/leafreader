# LR-019 — Защитить импорт и рендеринг повреждённых файлов

- **Статус:** open
- **Приоритет:** P0
- **Этап:** M3
- **Зависимости:** [LR-007](007-file-import.md), [LR-010](010-fb2-reader.md), [LR-011](011-epub-reader.md), [LR-012](012-pdf-reader.md), [LR-013](013-djvu-reader.md), [LR-014](014-custom-fonts.md)
- **Платформы:** iOS и Android
- **Ответственный:** не назначен

## Цель

Предотвратить падения, выход из каталога импорта и неконтролируемый расход ресурсов.

## Объём работ

- Задать лимиты архивов/XML/изображений/шрифтов, запретить XXE, path traversal и scripts.
- Проверить декодеры на повреждённом корпусе и применить подходящее fuzz-тестирование.
- Проверить ссылки, внешние ресурсы, очистку временных данных и отсутствие содержимого книг в логах.

## Критерии готовности

- [ ] ZIP bomb, внешняя XML-сущность и выход пути за каталог отклоняются.
- [ ] Битые файлы каждого формата и шрифты дают контролируемую ошибку без повреждения данных.
- [ ] Ресурсы книги не вызывают автоматических сетевых запросов; внешняя ссылка требует действия пользователя.
- [ ] Лимиты документированы; ошибки нехватки памяти/диска не оставляют незавершённый импорт.

## Проверка и результат

Приложить к задаче ссылки на изменения и результаты проверки критериев. Для исследовательской задачи — решение и измерения; для реализации — сценарии обеих платформ, существенные тесты и известные ограничения. Отмечать критерии после проверки.
